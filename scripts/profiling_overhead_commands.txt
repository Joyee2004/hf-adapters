Profiling overhead test: before vs after changes
================================================

Measures TTFT, steady ITL, Gen s and wall clock for three modes, as the median
of 5 runs (each mode is run 6 times and the first run is dropped):
  1. no profiling
  2. --with-profiling
  3. --with-profiling + PROFILE_LEVEL=light

scripts/run_profiling_overhead.sh does one whole set (all three modes,
interleaved, 6 passes) for one code version. Run it once on the code WITHOUT
your changes (before), switch the installed packages, then run it again WITH
your changes (after). Every run uses:

  --dtype float16 --prompt-file scripts/prompts.txt --batch 16
  --max-new-tokens 128 --min-new-tokens 128


0. SETUP (once per pod session)
-------------------------------

cd ~/hf_adapters
tmux new -s overhead        # 18 runs take a while; survives a dropped connection

The script sets PYTHONPATH, unsets PROFILE_LEVEL and creates traces/ itself.


1. BEFORE (code without your changes)
-------------------------------------

1 card:
    bash scripts/run_profiling_overhead.sh before

2 cards (valid indices are node-specific; one rank is launched per card):
    SPYRE_DEVICES=0,1 bash scripts/run_profiling_overhead.sh before

4 cards:
    SPYRE_DEVICES=0,1,2,3 bash scripts/run_profiling_overhead.sh before


2. AFTER (code with your changes)
---------------------------------

Switch the installed packages (flex etc.) to the version with your changes, and
check the switch took effect (pip show / git commit / loaded .so path). Clear
the compile caches if you want build time included in the comparison.

Then run the same command as BEFORE, with the name changed and the SAME
SPYRE_DEVICES and extra arguments:

    bash scripts/run_profiling_overhead.sh after
    # or: SPYRE_DEVICES=0,1 bash scripts/run_profiling_overhead.sh after

To compare several versions, give each its own name (after1, after2, ...).


3. COMPARE
----------

python3 scripts/compare_multicard_runs.py before.jsonl after.jsonl

Prints one before/after table per mode. More versions:
    python3 scripts/compare_multicard_runs.py before.jsonl after1.jsonl after2.jsonl

The compare script needs no torch, so you can also copy the JSONL files off the
pod and run it on a laptop:
    kubectl cp $NS/$POD:$HOME/hf_adapters/before.jsonl before.jsonl
    kubectl cp $NS/$POD:$HOME/hf_adapters/after.jsonl after.jsonl


Options
-------

REPEATS=N        passes over the three modes (default 6 -> median of 5)
                     REPEATS=3 bash scripts/run_profiling_overhead.sh quick
SPYRE_DEVICES    comma-separated card indices (default 0)
MASTER_PORT      torchrun port (default 29500); change it if 29500 is in use
extra arguments  passed on to every run, e.g.
                     bash scripts/run_profiling_overhead.sh before --max-new-tokens 256 --min-new-tokens 256

Background instead of tmux:
    nohup bash scripts/run_profiling_overhead.sh before_opt >/dev/null 2>&1 &
    tail -f before.log


Output of each set (NAME = before, after, ...)
----------------------------------------------

NAME.jsonl          18 lines (6 passes x 3 modes), written by rank 0, labels:
                      float16 b16 t128 ws1
                      float16 b16 t128 ws1 prof
                      float16 b16 t128 ws1 prof PROFILE_LEVEL=light
                    (ws2 / ws4 with 2 / 4 cards)
NAME.log            full console output, every rank's summary
traces/NAME_prof/   profiler traces for mode 2, one file per rank per run
traces/NAME_light/  profiler traces for mode 3, one file per rank per run


Notes
-----

- Model: the default, ibm-granite/granite-4.2-8b. It is not in
  tests/model_registry.py. The script's first run doubles as a check: if it
  fails (bad card index, model doesn't load, a buffer over the 256 MB
  per-core limit), the set stops instead of burning all 18 runs. Later
  failures are recorded with their status and the loop keeps going.
- Batch: 16 by default. Batch 64 fails to compile: prefill builds a
  [batch, 512, 100352] float16 logits buffer, 784 MB per core at batch 64.
  The buffer grows with batch, so try a larger one with a quick
  REPEATS=1 run (e.g. ... quick --batch 20) before a full set.
- The script refuses to overwrite: if NAME.jsonl exists, delete it or pick
  another name. Old runs would otherwise be mixed into the median.
- Don't pass --label (before/after are matched by the default label) or
  --iterations (each run is a fresh process with one timed generate).
- Keep SPYRE_DEVICES, extra arguments, the model and the pod the same for
  every version you compare. Labels end in ws<cards>, so different card counts
  are never matched against each other.
- Prompts: batch 16 uses the first 16 lines of scripts/prompts.txt, one per
  row.
- Wall s includes load and compile; Gen s / TTFT / ITL cover generation only.
  With a median of 5, treat differences of about 1-2% as noise.
