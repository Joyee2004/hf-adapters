Profiling overhead test: before vs after changes
================================================

Measures TTFT, steady ITL, Gen s, the per-run wall clock and the trace export
time for three modes:
  off    no profiling
  prof   --with-profiling
  light  --with-profiling + PROFILE_LEVEL=light

scripts/run_profiling_modes.py runs scripts/run_multicard_smoke.py once per
mode, one mode after another (all of off, then all of prof, then all of
light). Each mode is a single process: it loads and compiles once, does the
untimed warmup generate, then 6 timed generate runs. With profiling on,
torch.profiler.schedule(warmup=1, active=5) discards timed run 0 and records
runs 1-5 into one trace. Every rank writes one JSON line per timed run.

Run it once on the code WITHOUT your changes (before), switch the installed
packages, then run it again WITH your changes (after). Every run uses:

  --dtype float16 --prompt-file scripts/prompts.txt --batch 16
  --max-new-tokens 128 --min-new-tokens 128 --iterations 6


0. SETUP (once per pod session)
-------------------------------

cd ~/hf_adapters
tmux new -s overhead        # survives a dropped connection

The runner sets PYTHONPATH, SPYRE_DEVICES (default 0) and PROFILE_LEVEL (only
for light) itself.


1. BEFORE (code without your changes)
-------------------------------------

1 card:
    python3 scripts/run_profiling_modes.py --out before.jsonl

2 cards (valid indices are node-specific; one rank is launched per card):
    SPYRE_DEVICES=0,1 python3 scripts/run_profiling_modes.py --out before.jsonl

4 cards:
    SPYRE_DEVICES=0,1,2,3 python3 scripts/run_profiling_modes.py --out before.jsonl

Put SPYRE_DEVICES=... on the same line, or export it first. On a line of its
own without export it never reaches the runner, which then uses card 0.


2. AFTER (code with your changes)
---------------------------------

Switch the installed packages (flex etc.) to the version with your changes, and
check the switch took effect (pip show / git commit / loaded .so path). Clear
the compile caches if you want build time included in the comparison.

Then run the same command as BEFORE with another --out, and the SAME
SPYRE_DEVICES and extra arguments:

    python3 scripts/run_profiling_modes.py --out after.jsonl
    # or: SPYRE_DEVICES=0,1 python3 scripts/run_profiling_modes.py --out after.jsonl

To compare several versions, give each its own name (after1, after2, ...).


3. COMPARE
----------

python3 scripts/compare_multicard_runs.py before.jsonl after.jsonl

Prints one before/after table per mode (per mode and card on multi-card
runs). More versions:
    python3 scripts/compare_multicard_runs.py before.jsonl after1.jsonl after2.jsonl

The compare script needs no torch, so you can also copy the JSONL files off the
pod and run it on a laptop:
    kubectl cp $NS/$POD:$HOME/hf_adapters/before.jsonl before.jsonl
    kubectl cp $NS/$POD:$HOME/hf_adapters/after.jsonl after.jsonl


Options
-------

--iterations N     timed runs per mode (default 6). Profiled modes need at
                   least --profile-warmup + --profile-active (1 + 5).
--modes off,prof   which modes to run, in this order (default off,prof,light)
--rounds N         interleave: run every mode once per round, as its own
                   process, reversing the order every other round. Use this
                   for TTFT / ITL: e.g. --rounds 4 gives 4 independent
                   processes per mode, and the compare adds a paired
                   per-round table with a 95% interval and a verdict
                   (higher / lower / noise) for each mode against off.
                       python3 scripts/run_profiling_modes.py --out before.jsonl --rounds 4 -- --batch 4
                   Add --per-round to the compare to see each round's own
                   table of durations, e.g. to spot one round that is off:
                       python3 scripts/compare_multicard_runs.py before.jsonl --per-round
--master-port P    torchrun port (default 29500); change it if 29500 is in use
--trace-root DIR   where the per-mode trace directories go (default
                   /tmp/spyre_traces, local disk). Keep it off network or
                   shared filesystems, where export time varies run to run.
-- ARGS            passed on to every run_multicard_smoke.py run, replacing a
                   default they repeat, e.g.
                       python3 scripts/run_profiling_modes.py --out before.jsonl -- --batch 4
                   or a different profiler window (then raise --iterations):
                       ... --iterations 11 -- --profile-warmup 1 --profile-active 10

Background instead of tmux:
    SPYRE_DEVICES=0,1 nohup python3 scripts/run_profiling_modes.py --out before.jsonl >before.out 2>&1 &
    tail -f before.out

Without the runner, one mode is a single run_multicard_smoke.py command, e.g.
the prof mode on 2 cards:
    SPYRE_DEVICES=0,1 torchrun --nproc-per-node=2 --master-port=29500 scripts/run_multicard_smoke.py \
        --dtype float16 --prompt-file scripts/prompts.txt --batch 16 \
        --max-new-tokens 128 --min-new-tokens 128 --iterations 6 \
        --with-profiling --trace-dir /tmp/spyre_traces/before_prof --results-json before.jsonl


Output of each set (OUT = before.jsonl, ...; NAME = before, ...)
-----------------------------------------------------------------

OUT                one line per rank per timed run: 18 lines on 1 card (3
                   modes x 6 runs), 36 on 2 cards, 72 on 4. Labels:
                     float16 b16 t128 ws1
                     float16 b16 t128 ws1 prof
                     float16 b16 t128 ws1 prof PROFILE_LEVEL=light
                   With 2 / 4 cards the labels end in ws2 / ws4, and the
                   compare shows one row per card (... rank0, ... rank1).
NAME.<mode>.log    console output of each mode, every rank's summary
/tmp/spyre_traces/NAME_prof/   one trace per rank, covering timed runs 1-5
/tmp/spyre_traces/NAME_light/  the same for the light mode
                   Traces go to local disk by default (--trace-root to
                   change it): export time depends on the filesystem. Copy
                   them off before the pod restarts, e.g.
                     kubectl cp $NS/$POD:/tmp/spyre_traces ./spyre_traces


Notes
-----

- Model: the default, ibm-granite/granite-4.2-8b. It is not in
  tests/model_registry.py, so do one quick run first (--modes off
  --iterations 1) to check it loads.
- Batch: 16 by default. Batch 64 fails to compile: prefill builds a
  [batch, 512, 100352] float16 logits buffer, 784 MB per core at batch 64.
- The runner calls sync before every mode (its time is printed as
  "sync: N s"), so trace data still being flushed to disk from the previous
  mode can't slow the next one.
- A mode that fails is recorded with its status and the next mode still runs;
  the runner exits 1 if any mode failed.
- The runner refuses to overwrite: if OUT exists, delete it or pick another
  name. Old runs would otherwise be mixed into the mean.
- Don't pass --label (before/after are matched by the default label).
- The compare drops timed run 0 of every mode (the profiler's warmup; also
  dropped for off so all modes cover the same runs) and takes the mean of
  runs 1-5. Keep the iteration counts and the profiler window the same for
  every version: the export is spread over the profiled runs (below), so
  Wall s overhead depends on how many there are.
- Each mode is one process, so Load and Warmup are measured once per mode and
  repeated on its lines. Gen s, Wall s, Wall-exp s, TTFT and ITL are per timed
  run, and the compare shows their mean over runs 1-5. Wall s is a run's
  wall clock from its start to the start of the next one: generate, the
  profiler step (including any export) and the output checks.
- Export s is the whole profiler step that closes the window after run 5:
  stopping the profiler, parsing its events and writing the trace. It is
  shown once per trace (summed over the process's runs), not per run. Only
  run 5's Wall s carries it, so the mean Wall s of a profiled mode includes
  Export s / 5; Wall-exp s is Wall s minus the export. Report Wall s for the
  full wall clock including the export, and Export s on its own.
- Before every timed run, in every mode, the script runs gc.collect() and
  disables garbage collection until the run's generate and profiler step are
  done, so a collection pause can't land at a random token. On multi-card
  runs all ranks then meet at a barrier, so every run starts on all cards at
  once. Neither the collect nor the barrier is in any measured time.
- On multi-card runs the compare adds a "... max" row per mode: for every
  run, the slowest card's value of each metric. Use it for the job's wall
  clock and export: a TP run is only done when its last card is.
- Per-token times (TTFT, ITL) use time.perf_counter(), a monotonic clock.
  Older files were recorded with time.time(); record before and after with
  the same code.
- Treat single differences of about 1-2% as noise. Modes run one after
  another, so node noise that comes and goes can land on one mode only. Use
  --rounds 4 or more and read the paired table, which says whether a
  difference is outside noise.
